# AppSheet Configuration Guide
## Reimbursement Management App

This guide walks you through building the mobile + web app in AppSheet,
connected to your Google Sheets backend.

---

## Prerequisites

- Google Sheet initialized with `setupAll()` (see README.md)
- A Google account with AppSheet access (free tier is sufficient)
- Finance team email updated in the **Settings** sheet

---

## Part 1 — Connect AppSheet to Google Sheets

1. Go to [appsheet.com](https://www.appsheet.com) and sign in with your Google account.
2. Click **Create** → **App** → **Start with your own data**.
3. Choose **Google Sheets** as the data source.
4. Select your initialized reimbursement spreadsheet.
5. AppSheet will detect all sheets automatically. Click **Customize your app**.

---

## Part 2 — Configure Data Tables

Navigate to **Data** → **Tables** in the left sidebar. Configure each table:

### Employees Table

| Setting | Value |
|---------|-------|
| Key column | `EmployeeID` |
| Label column | `FullName` |
| Read-only columns | `EmployeeID`, `JoinDate` |
| Hidden columns (from employees) | `BankAccount`, `ManagerEmail` |
| Security filter | `[Email] = USEREMAIL()` ← employees see only themselves |

### ExpenseClaims Table

| Setting | Value |
|---------|-------|
| Key column | `ClaimID` |
| Label column | `ClaimID` |
| Default value for `SubmissionDate` | `NOW()` |
| Default value for `Status` | `"Pending"` |
| Default value for `EmployeeID` | `LOOKUP(USEREMAIL(), "Employees", "Email", "EmployeeID")` |
| Default value for `EmployeeName` | `LOOKUP(USEREMAIL(), "Employees", "Email", "FullName")` |

**Column types:**

| Column | AppSheet Type | Notes |
|--------|--------------|-------|
| `ClaimID` | Text | Auto-generated by Apps Script |
| `SubmissionDate` | DateTime | Read-only for employees |
| `ExpenseDate` | Date | Required |
| `Category` | Enum | Source: `Categories[CategoryName]` |
| `Amount` | Decimal | Required |
| `Currency` | Enum | Values: USD, EUR, GBP, INR, AED, SGD |
| `ReceiptURL` | File | Allows photo/PDF upload |
| `Status` | Enum | Editable only by Finance role |
| `ReviewNotes` | LongText | Editable only by Finance role |
| `ApprovedAmount` | Decimal | Editable only by Finance role |

### Advances Table

| Setting | Value |
|---------|-------|
| Key column | `AdvanceID` |
| Label column | `AdvanceID` |
| Read-only for employees | All columns except `Purpose` (view only) |

### Ledger Table

| Setting | Value |
|---------|-------|
| Read-only | ALL columns (this is a calculated view) |
| Show to | Finance role only |

### Categories Table

| Setting | Value |
|---------|-------|
| Read-only | All columns |
| Used as reference | For ExpenseClaims Category dropdown |

## Part 3 — Security & Roles

Navigate to **Security** → **Roles**.

### Create Two Roles

#### Role: Employee

```
Permissions:
  Employees:    Read (own row only)
  ExpenseClaims: Read + Add (own rows only)
  Advances:     Read (own rows only)
  Ledger:       Read (own row only)
  Categories:   Read

Row filter on ExpenseClaims:
  [EmployeeID] = LOOKUP(USEREMAIL(), "Employees", "Email", "EmployeeID")

Row filter on Ledger:
  [EmployeeID] = LOOKUP(USEREMAIL(), "Employees", "Email", "EmployeeID")
```

#### Role: Finance

```
Permissions:
  Employees:    Read + Edit
  ExpenseClaims: Read + Edit (all rows)
  Advances:     Read + Add + Edit
  Ledger:       Read (all rows)
  Categories:   Read + Edit + Add

No row filter (Finance sees all data)
```

### Assign Users to Roles

Go to **Security** → **Users** and add:
- All employee email addresses → **Employee** role
- Finance team emails → **Finance** role

## Part 4 — Views (App Screens)

Navigate to **UX** → **Views**. Create the following views:

### Employee-facing Views

#### My Claims (primary view for employees)
```
View type:   Table or Deck
Data:        ExpenseClaims
Sort:        SubmissionDate (descending)
Group by:    Status
Search:      On
```

#### Submit Claim (form view)
```
View type:   Form
Data:        ExpenseClaims
Visible columns:
  - ExpenseDate (required)
  - Category (required, dropdown)
  - Description (required)
  - Amount (required)
  - Currency
  - ReceiptURL (file upload, label: "Attach Receipt")
Hidden/auto-filled:
  - ClaimID (hidden, set by Apps Script)
  - EmployeeID (auto from USEREMAIL)
  - EmployeeName (auto)
  - SubmissionDate (auto)
  - Status (auto = Pending)
```

#### My Advances
```
View type:   Table
Data:        Advances
Filter:      [EmployeeID] = LOOKUP(USEREMAIL(), "Employees", "Email", "EmployeeID")
```

#### My Balance (dashboard)
```
View type:   Dashboard or Detail
Data:        Ledger (own row)
Displays:
  - TotalClaimed
  - TotalApproved
  - TotalAdvances
  - NetBalance (highlighted: green if positive, red if negative)
  - PendingApproval
```

---

### Finance-facing Views

#### All Claims (review queue)
```
View type:   Table
Data:        ExpenseClaims
Sort:        SubmissionDate (ascending, oldest first)
Group by:    Status
Filter:      Show Pending first
Quick-edit:  Status column (inline edit)
```

#### Claim Detail (Finance review)
```
View type:   Detail
Data:        ExpenseClaims
Editable fields:
  - Status (dropdown: Pending / Approved / Rejected / Paid)
  - ReviewNotes
  - ApprovedAmount
  - PaymentRef
  - PaymentDate
Actions:
  - Approve (sets Status = Approved, auto-fills ApprovedAmount)
  - Reject (sets Status = Rejected, requires ReviewNotes)
  - Mark Paid (sets Status = Paid, sets PaymentDate = today)
```

#### Finance Ledger
```
View type:   Table
Data:        Ledger
Sort:        NetBalance (descending)
Columns:     All
Export:      Enable "Download as CSV"
```

#### Advances Management
```
View type:   Table
Data:        Advances
Sort:        IssueDate (descending)
Actions:     Add new advance
```

## Part 5 — Actions

Navigate to **Behavior** → **Actions**. Create these custom actions:

### Action: Approve Claim
```
Table:        ExpenseClaims
Action type:  Data: set the values of some columns in this row
Condition:    [Status] = "Pending"
Set columns:
  Status = "Approved"
  ApprovedAmount = IF([ApprovedAmount] = "", [Amount], [ApprovedAmount])
  ReviewedBy = USEREMAIL()
  ReviewDate = NOW()
Confirmation: "Approve this claim for [Amount]?"
Icon: check-circle (green)
```

### Action: Reject Claim
```
Table:        ExpenseClaims
Action type:  Data: set the values of some columns in this row
Condition:    [Status] = "Pending"
Set columns:
  Status = "Rejected"
  ReviewedBy = USEREMAIL()
  ReviewDate = NOW()
Requires:     ReviewNotes must be filled
Confirmation: "Reject this claim? The employee will be notified."
Icon: x-circle (red)
```

### Action: Mark as Paid
```
Table:        ExpenseClaims
Action type:  Data: set the values of some columns in this row
Condition:    [Status] = "Approved"
Set columns:
  Status = "Paid"
  PaymentDate = TODAY()
Confirmation: "Mark this claim as paid? This cannot be undone."
Icon: dollar-sign (blue)
```

### Action: Issue Advance (Finance only)
```
Table:        Advances
Action type:  App: go to another view within this app
Target:       Add new advance form
Visibility:   Finance role only
```

## Part 6 — Automations (AppSheet Automations)

Navigate to **Behavior** → **Automations**.

### Automation 1: New Claim Alert to Finance
```
Trigger:      A row is added to ExpenseClaims
Condition:    [Status] = "Pending"
Action:       Send an email
  To:         GET("Settings", "FINANCE_EMAIL", "Key", "Value")
  Subject:    "New Reimbursement Claim: [ClaimID] from [EmployeeName]"
  Body:       Use email template (include ClaimID, Amount, Category, ReceiptURL)
```

> Note: If using Apps Script email notifications (recommended), disable this
> to avoid duplicate emails. The Apps Script trigger handles this already.

### Automation 2: Status Change Alert to Employee
```
Trigger:      A row is updated in ExpenseClaims
Condition:    [Status] <> [_THISROW_BEFORE].[Status]
              AND [Status] <> "Pending"
Action:       Send an email
  To:         LOOKUP([EmployeeID], "Employees", "EmployeeID", "Email")
  Subject:    "Your Claim [ClaimID] — Status: [Status]"
  Body:       Include Status, ApprovedAmount, NetPayable, ReviewNotes
```

> Same note: disable if using Apps Script email-notifications.gs.

## Part 7 — Branding & Mobile UX

Navigate to **UX** → **Brand**:

1. **App Name:** `Expense Manager` (or your company name)
2. **Icon:** Upload your company logo (square, 512×512px recommended)
3. **Primary color:** Choose your brand color
4. **Theme:** Light or Dark depending on preference

Navigate to **UX** → **Options**:
- Enable **Offline mode** (employees can fill forms without internet; syncs when connected)
- Enable **Show column descriptions** (helps employees fill forms correctly)

## Part 8 — Deployment

### Deploy for Mobile

1. Go to **Manage** → **Deploy** → **Move app to deployed state**.
2. Share the app link with employees: `https://www.appsheet.com/start/YOUR_APP_ID`
3. Employees install it as a PWA (Progressive Web App) on their phone:
   - **iOS:** Safari → Share → Add to Home Screen
   - **Android:** Chrome → Menu → Add to Home Screen

### Deploy for Desktop

The same AppSheet URL works in any browser on laptop/desktop.
Employees and finance can bookmark it or use it directly.

### Share with Users

Go to **Manage** → **Users**:
- Add employee emails (they receive an invitation email with the app link)
- Assign roles: Employee or Finance

## Part 9 — Testing Checklist

Before going live, test the following:

- [ ] Employee can log in and see only their own claims
- [ ] Employee can submit a new claim with a receipt photo
- [ ] Finance receives email notification for new submission
- [ ] Finance can approve a claim; employee receives approval email
- [ ] Finance can reject a claim with notes; employee receives rejection email
- [ ] Advance is automatically deducted from net payable on approval
- [ ] Ledger updates correctly after approval
- [ ] Finance can mark a claim as paid; employee receives payment email
- [ ] PDF export generates correctly and is emailed
- [ ] Excel export downloads correctly
- [ ] Monthly summary trigger fires (test by manually calling `sendMonthlyFinanceSummary()`)
- [ ] Mobile layout renders correctly on iOS and Android

## Troubleshooting

| Issue | Solution |
|-------|----------|
| AppSheet can't see new sheets | Data → Tables → Add new table → select sheet |
| Email not sending | Check that `FINANCE_EMAIL` in Settings sheet is correct. Verify GmailApp permission was granted when running `installTriggers()`. |
| Status change not triggering | Verify `onClaimStatusChange` trigger is installed (run `listTriggers()` in Apps Script editor) |
| PDF export fails | Check that the Apps Script has Drive and external URL fetch permissions |
| Advance not deducting | Ensure advance Status = "Outstanding" in Advances sheet |
| Ledger shows wrong totals | Run `rebuildLedger()` manually from the custom menu |
